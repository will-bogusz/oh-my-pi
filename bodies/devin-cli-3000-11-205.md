## What

I bumped the Devin pin to 3000.11.205 because that's what the CLI ships now, and omp was still telling Devin's backend it was 3000.11.3.

Devin chat, model assignment and `/usage` requests now identify as CLI 3000.11.3 → 3000.11.205. The identity is one constant (`DEVIN_CLI_METADATA` in `packages/catalog/src/wire/devin.ts`); the other identity fields (`devin-cli` / `chisel`) and model discovery's separate dev-channel identity are unchanged.

## Why

Devin's backend gates behaviour on the client identity a request carries (`chisel` is what unlocks router assignment), and 3000.11.3 is no longer what the official CLI sends: 3000.11.92 and now 3000.11.205 shipped since. Today's official CLI sends the same `devin-cli` / `chisel` identity with 3000.11.205 in both version fields, so this is the version string only, as in `30f532944f5`.

Non-goals: the other request changes newer CLIs make (HTTP/2, per-message prompt cache options, a different auth path) stay as they are; nothing here needs them, and omp's current request shape completes turns under the new identity (Testing).

Related: #16172 (GPT turns bill Devin quota instead of a linked ChatGPT plan; the old pin is one suspect there). This PR does not claim to fix it.

Maintenance: the pin is hand-maintained. The current release is `version` in `https://static.devin.ai/cli/current/manifest.json`; bumping it is this same three-line change.
